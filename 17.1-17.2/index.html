17.1The big idea

A kernel is a similarity score that is secretly an inner product.

So far most models in the book have been parametric: you choose a feature vector $\boldsymbol\phi(\mathbf{x})$, then learn weights $\mathbf{w}$ so that $f(\mathbf{x}) = \mathbf{w}^\top\boldsymbol\phi(\mathbf{x})$. Chapter 17 flips this around. Instead of saying what the features are, you say how similar two inputs are:

A kernel
$$\mathcal{K}(\mathbf{x}, \mathbf{x}') \in \mathbb{R}, \qquad \text{large when } \mathbf{x} \text{ and } \mathbf{x}' \text{ are "alike"}$$

The prediction at a new point is then built from the training points it is similar to. The catch is that not every similarity score is allowed. A Mercer kernel is one that behaves like an inner product $\boldsymbol\phi(\mathbf{x})^\top\boldsymbol\phi(\mathbf{x}')$ for some feature map $\boldsymbol\phi$, possibly with infinitely many features. That gives you two things:

  1. The kernel trick. You can work in a huge (even infinite) feature space while only ever computing $\mathcal{K}$ on pairs of inputs, which is often a one-line formula.
  2. A valid prior over functions. A Mercer kernel can be used as the covariance of a Gaussian process: $\mathrm{Cov}[f(\mathbf{x}), f(\mathbf{x}')] = \mathcal{K}(\mathbf{x}, \mathbf{x}')$. Choosing the kernel is choosing what kind of functions you expect (smooth, rough, periodic, trending…).

The page is in three parts. Part 1 asks what makes a kernel valid and shows the two-way bridge between kernels and features. Part 2 is a zoo of kernels and the rules for generating new ones. Part 3 uses kernels for Gaussian-process regression, including learning the kernel's settings from data and forecasting a seasonal time series.

Not the same "kernel" as §16.3. A density kernel (KDE) only needs to be a symmetric bump that integrates to 1. A Mercer kernel needs no normalization, can take negative values, and doesn't even need to be a bump (the linear kernel $\mathbf{x}^\top\mathbf{x}'$ is one), but it must pass a stricter test: positive semidefiniteness. Demo 1 shows that the boxcar and Epanechnikov kernels from §16.3 fail it.

Part 1 · What makes a kernel a kernel

The positive-definite condition, why it matters, and the bridge between kernels and feature vectors.

17.1Mercer kernels and positive-definite Gram matrices

Pick any points. Build the table of all pairwise similarities. That table must look like a covariance matrix.

Given $N$ inputs, the Gram matrix collects every pairwise similarity: $K_{ij} = \mathcal{K}(\mathbf{x}_i, \mathbf{x}_j)$. A symmetric function $\mathcal{K}$ is a Mercer kernel (also called a positive definite kernel) if, for every choice of points and every vector of coefficients $\mathbf{c}$,

Mercer condition
$$\sum_{i=1}^{N}\sum_{j=1}^{N}\mathcal{K}(\mathbf{x}_i,\mathbf{x}_j)\,c_i c_j \;=\; \mathbf{c}^\top\mathbf{K}\,\mathbf{c} \;\ge\; 0 \qquad\Longleftrightarrow\qquad \text{all eigenvalues of } \mathbf{K} \text{ are } \ge 0.$$

Why this exact condition? Suppose $\mathcal{K}$ is the covariance of a random function $f$. Then for any coefficients, $\mathrm{Var}\big[\sum_i c_i f(\mathbf{x}_i)\big] = \mathbf{c}^\top\mathbf{K}\mathbf{c}$. A variance can't be negative, so a covariance function must satisfy the condition. Conversely, if the condition holds, $\mathbf{K}$ is a legal covariance matrix and you can sample $\big(f(\mathbf{x}_1),\dots,f(\mathbf{x}_N)\big) \sim \mathcal{N}(\mathbf{0}, \mathbf{K})$. The same condition is what makes $\mathcal{K}$ an inner product of feature vectors, as the next section shows.

Things to try. With squared exponential, drag two points on top of each other: two rows of $\mathbf{K}$ become identical, so one eigenvalue drops to 0. That is still allowed (semi-definite). With the boxcar, every configuration of 10 spread-out points fails. With Epanechnikov, failure depends on where the points are, so drag them around until a red bar appears. One failing configuration is enough to disqualify a kernel. With tanh (the "sigmoid kernel" sometimes used with SVMs), the Gram matrix is badly indefinite.

A quick test for the stationary case. If $\mathcal{K}(\mathbf{x},\mathbf{x}') = k(\mathbf{x}-\mathbf{x}')$ depends only on the difference, Bochner's theorem says $\mathcal{K}$ is Mercer exactly when the Fourier transform of $k$ is non-negative. The Gaussian's transform is another Gaussian (positive everywhere), so it passes. The boxcar's transform is a sinc, which dips below zero, so it fails. The Fourier view comes back in the random-features demo.

17.1.1Mercer's theorem: every kernel is an inner product

A positive semidefinite matrix can always be factored, and the factors are feature vectors.

Because $\mathbf{K}$ is symmetric and positive semidefinite, its eigendecomposition is $\mathbf{K} = \mathbf{U}^\top\boldsymbol\Lambda\mathbf{U}$ with all $\lambda_m \ge 0$. Define a feature vector for each point from the columns of $\mathbf{U}$: $\boldsymbol\phi(\mathbf{x}_i) = \boldsymbol\Lambda^{1/2}\mathbf{U}_{:,i}$. Then

Finite version (any Gram matrix)
$$K_{ij} = \boldsymbol\phi(\mathbf{x}_i)^\top\boldsymbol\phi(\mathbf{x}_j).$$
Mercer's theorem (continuous version)
$$\mathcal{K}(\mathbf{x}, \mathbf{x}') = \sum_{m=1}^{\infty} \lambda_m\,\phi_m(\mathbf{x})\,\phi_m(\mathbf{x}'),\qquad \lambda_m \ge 0.$$

The square root $\boldsymbol\Lambda^{1/2}$ only exists because the eigenvalues are non-negative. That is the real reason for the Mercer condition. It also explains why the impostors in Demo 1 are useless: no feature space reproduces them.

The classic hand-worked example is the quadratic kernel in 2D, $\mathcal{K}(\mathbf{x},\mathbf{x}') = (\mathbf{x}^\top\mathbf{x}')^2$. Expanding,

$$(x_1x_1' + x_2x_2')^2 = x_1^2x_1'^2 + 2x_1x_2x_1'x_2' + x_2^2x_2'^2 = \boldsymbol\phi(\mathbf{x})^\top\boldsymbol\phi(\mathbf{x}'),\qquad \boldsymbol\phi(\mathbf{x}) = \big[x_1^2,\ \sqrt2\,x_1x_2,\ x_2^2\big].$$

So the kernel secretly maps 2D points into 3D. A problem that is not linearly separable in 2D (a disc inside a ring) becomes separable by a plane in 3D, because $\phi_1+\phi_3 = x_1^2 + x_2^2$ is the squared radius.

For the polynomial kernel $(\mathbf{x}^\top\mathbf{x}')^M$ in $D$ dimensions, the feature vector contains every monomial of degree $M$. Computing the kernel directly costs about $D$ multiplications, regardless of $M$.

17.1.1How kernels are generated, part 1: features → kernel

Pick any feature map. Its inner product is automatically a Mercer kernel.

Mercer's theorem runs both ways. Whenever $\mathcal{K}(\mathbf{x},\mathbf{x}') = \sum_m \phi_m(\mathbf{x})\phi_m(\mathbf{x}')$, the condition holds automatically: $\mathbf{c}^\top\mathbf{K}\mathbf{c} = \sum_m\big(\sum_i c_i\phi_m(\mathbf{x}_i)\big)^2 \ge 0$, a sum of squares. So one way to generate a kernel is to choose features and take their inner product.

There is a probabilistic reading too. Put independent standard-normal weights on the features, $f(x) = \sum_m w_m\phi_m(x)$ with $w_m\sim\mathcal{N}(0,1)$. Then $\mathrm{Cov}[f(x), f(x')] = \sum_m \phi_m(x)\phi_m(x')$. The kernel is the covariance of a random linear model. This is the "weight-space view" of a Gaussian process (§17.2.4).

Below, three very different feature families all converge to the same kernel, the squared exponential $\exp\!\big(-(x-x')^2/2\ell^2\big)$, as you add features. That shows two things: the SE kernel has infinitely many features, and the feature map for a given kernel is not unique.

  • Taylor features $\phi_m(x) = e^{-x^2/2\ell^2}\,(x/\ell)^m/\sqrt{m!}$, for $m=0,1,2,\dots$ Polynomials under a Gaussian envelope.
  • Gaussian bumps placed at evenly spaced centers $c_m$, $\phi_m(x) \propto e^{-(x-c_m)^2/\ell^2}$. These are RBF-network features.
  • Random Fourier features $\phi_m(x) = \sqrt{2/M}\cos(\omega_m x + b_m)$, $\omega_m\sim\mathcal{N}(0, 1/\ell^2)$, $b_m\sim\mathrm{Unif}(0, 2\pi)$. Random waves (Rahimi & Recht). By Bochner's theorem, the average of $\cos(\omega(x-x'))$ over this $\omega$ distribution is the SE kernel.

What to notice. Taylor features are exact near 0 and fail far from 0, where higher powers are needed. Bumps give a lumpy kernel until the centers are closer together than $\ell$. Random features converge everywhere but slowly, with error shrinking roughly like $1/\sqrt{M}$. With few features, the random functions look like the features (a few bumps, a few waves). With many, they all start to look like the same smooth SE functions. Random Fourier features are a real tool for scaling kernel methods to large data (§17.2.9).

17.1.1How kernels are generated, part 2: kernel → features

Start from a kernel formula and recover its features by eigendecomposition.

Going the other way, any Mercer kernel can be eigendecomposed into its own feature functions. Here we take 80 grid points on $[-5,5]$, build $\mathbf{K}$, and compute its eigenvectors. Each eigenvector, plotted against $x$, approximates one Mercer eigenfunction $\phi_m(x)$, and the eigenvalue $\lambda_m$ says how much that feature contributes. Truncating to the top $M$ terms gives the best rank-$M$ approximation of the kernel.

The eigen-features look like waves of increasing frequency. That is not a coincidence: for a stationary kernel they approach Fourier modes, and the eigenvalues follow the kernel's spectrum. A larger ℓ means a smoother kernel, faster eigenvalue decay, and fewer features that matter. Matérn ½ is rough, so its spectrum decays slowly and you need many features. The linear kernel has exactly two non-zero eigenvalues (a constant and a slope), so it is a finite-dimensional kernel.

17.1.2One length-scale per dimension: the ARD kernel

Give every input dimension its own length-scale, and let the data decide which ones matter.

In $D$ dimensions, the SE kernel can use a separate length-scale per dimension:

Automatic relevance determination (ARD)
$$\mathcal{K}(\mathbf{x},\mathbf{x}') = \sigma^2\exp\!\Big(-\tfrac12\sum_{d=1}^{D}\frac{(x_d-x'_d)^2}{\ell_d^2}\Big)$$

If $\ell_d$ is huge, moving along dimension $d$ barely changes the similarity, so $f$ effectively ignores $x_d$. When the $\ell_d$ are learned from data (as in §17.2.6), irrelevant inputs get large length-scales and are switched off automatically. 17.1.2Making new kernels from old

A small set of closure rules turns the linear kernel into the whole zoo.

Checking the Mercer condition from scratch is hard. In practice you build kernels with operations that are guaranteed to keep the Gram matrix PSD. If $\mathcal{K}_1$ and $\mathcal{K}_2$ are valid kernels, so are:

New kernelWhy it stays PSD
$c\,\mathcal{K}_1(\mathbf{x},\mathbf{x}')$, $c>0$scaling all eigenvalues by $c>0$ keeps them $\ge 0$
$f(\mathbf{x})\,\mathcal{K}_1(\mathbf{x},\mathbf{x}')\,f(\mathbf{x}')$, any $f$$\mathbf{K} \mapsto \mathbf{D}\mathbf{K}\mathbf{D}$ with $\mathbf{D}=\mathrm{diag}(f(\mathbf{x}_i))$; features become $f(\mathbf{x})\boldsymbol\phi(\mathbf{x})$
$\mathbf{x}^\top\mathbf{A}\,\mathbf{x}'$, $\mathbf{A}\succeq 0$features $\mathbf{A}^{1/2}\mathbf{x}$
$\mathcal{K}_1 + \mathcal{K}_2$$\mathbf{c}^\top(\mathbf{K}_1+\mathbf{K}_2)\mathbf{c}$ is a sum of two non-negative terms; features are concatenated
$\mathcal{K}_1\cdot\mathcal{K}_2$Schur product theorem; features are all pairwise products $\phi_a\psi_b$
$q\big(\mathcal{K}_1\big)$, $q$ a polynomial with coefficients $\ge 0$sums and products of the above
$\exp\big(\mathcal{K}_1\big)$the limit of such polynomials (its Taylor series)

17.1.2Combining kernels by addition and multiplication

Adding kernels is like OR: f is a sum of independent parts. Multiplying is like AND: points are similar only if both kernels agree.

If $f_1\sim\mathcal{GP}(0,\mathcal{K}_1)$ and $f_2\sim\mathcal{GP}(0,\mathcal{K}_2)$ are independent, then $f_1+f_2 \sim \mathcal{GP}(0, \mathcal{K}_1+\mathcal{K}_2)$. A sum of kernels therefore models a function made of separate additive components (trend plus seasonality). A product gives high similarity only when both factors are high. For example, SE × Periodic means "repeats with period $p$, and only for nearby points", so the repeating pattern can slowly change shape. Lin × Periodic has an oscillation whose amplitude grows with $|x-c|$. This mini-language is the basis of automatic kernel search ("the automatic statistician").

17.1.2Kernels for structured inputs

Kernels only need a similarity between two objects, so the inputs don't have to be vectors.

Because a kernel method touches the data only through $\mathcal{K}(\mathbf{x},\mathbf{x}')$, you can apply it to strings, graphs, trees or sets, as long as you can write down a valid kernel. The simplest string kernel is the $k$-spectrum kernel. Let $\phi_u(s)$ be the number of times the substring $u$ of length $k$ appears in string $s$. Then

$$\mathcal{K}(s, s') = \sum_{u\in\mathcal{A}^k}\phi_u(s)\,\phi_u(s'),$$ an inner product of (huge, sparse) count vectors, so it is Mercer by construction. It is usually normalized as $\tilde{\mathcal{K}}(s,s') = \mathcal{K}(s,s')/\sqrt{\mathcal{K}(s,s)\mathcal{K}(s',s')}$, which is itself the "$f(x)\mathcal{K}f(x')$" rule with $f = 1/\sqrt{\mathcal{K}(x,x)}$.

There are $|\mathcal{A}|^k$ possible substrings, but you never build the vector. You just count shared substrings. Variants allow gaps or weight longer matches more (used for protein sequences and text). Graph kernels similarly compare counts of shared walks or subtrees.

Part 3 · Application: Gaussian-process regression

Use the kernel as a covariance, condition on data, and get predictions with error bars. Choosing the kernel is the modelling.

17.2Gaussian processes: kernels as priors over functions

Before data, the kernel says what functions are plausible. After data, keep only the ones that pass near the points.

A Gaussian process $f\sim\mathcal{GP}(m, \mathcal{K})$ is a distribution over functions such that any finite set of values $\big(f(\mathbf{x}_1),\dots,f(\mathbf{x}_N)\big)$ is jointly Gaussian with mean $m(\mathbf{x}_i)$ and covariance $\mathcal{K}(\mathbf{x}_i,\mathbf{x}_j)$. This is why the kernel must be Mercer: every such covariance matrix has to be PSD. Observe $y_n = f(\mathbf{x}_n) + \epsilon_n$ with $\epsilon_n\sim\mathcal{N}(0,\sigma_y^2)$. Then, because everything is Gaussian, the prediction at test points $\mathbf{X}_*$ has a closed form:

GP posterior predictive (zero prior mean)
$$\boldsymbol\mu_{*} = \mathbf{K}_{X,*}^\top\,\mathbf{K}_\sigma^{-1}\,\mathbf{y},\qquad \boldsymbol\Sigma_{*} = \mathbf{K}_{*,*} - \mathbf{K}_{X,*}^\top\,\mathbf{K}_\sigma^{-1}\,\mathbf{K}_{X,*},\qquad \mathbf{K}_\sigma = \mathbf{K}_{X,X} + \sigma_y^2\mathbf{I}.$$

With $\sigma_y = 0$ (noise-free, §17.2.1), the mean passes exactly through every point and the uncertainty pinches to zero there, so the GP acts as an interpolator. With $\sigma_y>0$ (§17.2.2), it smooths. Far from the data, both revert to the prior: mean 0, spread $\pm 2\sigma_f$.

The GP mean is a linear smoother, $\mu(x_*) = \sum_n w_n(x_*)\,y_n$, just like Nadaraya–Watson from §16.3.5. The difference is in the weights. Nadaraya–Watson uses the kernel directly, normalized, so the weights are always positive and sum to 1. The GP's weights $\mathbf{K}_\sigma^{-1}\mathbf{k}_*$ (the "equivalent kernel") account for how the training points relate to each other. Two nearby points share their credit, isolated points get more, and weights can go negative. Turn on the comparison, put three points close together, and hover between them and further out to see this.

17.2.6Learning the kernel: the marginal likelihood

A built-in Occam's razor: the evidence rewards fitting the data but charges for flexibility.

The kernel's settings $\boldsymbol\theta = (\ell, \sigma_f, \sigma_y)$ are chosen by maximizing the probability of the observed $\mathbf{y}$ with $f$ integrated out:

Log marginal likelihood
$$\log p(\mathbf{y}\mid\mathbf{X},\boldsymbol\theta) = \underbrace{-\tfrac12\,\mathbf{y}^\top\mathbf{K}_\sigma^{-1}\mathbf{y}}_{\text{data fit}}\;\underbrace{-\;\tfrac12\log|\mathbf{K}_\sigma|}_{\text{complexity penalty}}\;-\;\tfrac N2\log 2\pi$$

A short length-scale lets the GP fit every wiggle (good data fit), but it spreads prior probability over a huge number of possible functions (big $|\mathbf{K}_\sigma|$, big penalty). A long length-scale is "cheap" but can't fit the wiggles. The 14 points below were built so that there are two good, nearly equally likely explanations: wiggly signal with little noise, or smooth signal with more noise.

ApplicationForecasting a seasonal series by composing kernels

Everything at once: pick kernel parts, and the GP decomposes the data and extrapolates each part in its own way.

Here is ten years of simulated monthly measurements (think atmospheric CO₂ or electricity demand): a rising, slightly curving trend, a yearly cycle with a second harmonic, some slow irregular drift, and measurement noise. The task is to forecast the next four years. The kernel is a sum of parts, so the GP models the data as a sum of independent functions, one per part:

$$\mathcal{K} = \underbrace{\sigma_1^2\,\mathrm{Lin}}_{\text{trend}} + \underbrace{\sigma_2^2\,\mathrm{SE}_{\ell=4}}_{\text{smooth trend}} + \underbrace{\sigma_3^2\,\mathrm{Per}_{p}\times\mathrm{SE}_{\ell=15}}_{\text{seasonal, slowly changing}} + \underbrace{\sigma_4^2\,\mathrm{SE}_{\ell=0.4}}_{\text{short-term}} + \sigma_y^2\,\delta_{xx'}$$

Each component's posterior mean is $\mathbf{K}^{(c)}_{X,*}{}^\top\mathbf{K}_\sigma^{-1}\mathbf{y}$: the same weights, but only that component's kernel. The total forecast is the sum of the components. Switch parts on and off, then reveal the true future to score the forecast.

17.2The rest of §17.2 in brief

Weight space vs. function space

Bayesian linear regression with features $\boldsymbol\phi(\mathbf{x})$ and prior $\mathbf{w}\sim\mathcal{N}(\mathbf{0},\boldsymbol\Sigma_w)$ gives exactly the same predictions as a GP with kernel $\mathcal{K}(\mathbf{x},\mathbf{x}') = \boldsymbol\phi(\mathbf{x})^\top\boldsymbol\Sigma_w\boldsymbol\phi(\mathbf{x}')$. Demo 3 is this statement. The weight-space version costs $O(M^3)$ in the number of features, and the function-space version costs $O(N^3)$ in the number of data points. With infinitely many features, only the function-space version is possible.

Numerical issues

Never invert $\mathbf{K}_\sigma$. Factor it as $\mathbf{K}_\sigma = \mathbf{L}\mathbf{L}^\top$ (Cholesky) and solve two triangular systems: $\boldsymbol\alpha = \mathbf{L}^{-\top}(\mathbf{L}^{-1}\mathbf{y})$, then $\boldsymbol\mu_* = \mathbf{K}_{X,*}^\top\boldsymbol\alpha$. The log-determinant comes for free as $2\sum_i\log L_{ii}$. Smooth kernels like SE produce nearly singular Gram matrices (Demo 4: the eigenvalues fall off a cliff), so a small "jitter" $\epsilon\mathbf{I}$ is added to the diagonal. Every demo on this page does exactly this, and the GP playground shows the jitter it needed.

GPs for classification

For labels, push the latent GP through a sigmoid: $p(y=1\mid\mathbf{x}) = \sigma(f(\mathbf{x}))$. The posterior is no longer Gaussian, so it is approximated (Laplace, variational inference, or EP). The kernel's role is unchanged: it encodes which inputs should get similar predictions.

Connections with deep learning

A neural network with one infinitely wide hidden layer and random Gaussian weights is a GP, with a kernel determined by the activation function (the neural-network GP). Deep versions give other kernels, and the neural tangent kernel describes how wide networks train. "Kernel" and "network" are closer than they look.

Scaling up

The $O(N^3)$ Cholesky becomes the bottleneck past roughly $10^4$ points. Standard fixes are low-rank approximations: inducing points (a small set of pseudo-inputs), or random Fourier features (Demo 3), which turn the GP back into Bayesian linear regression with $M \ll N$ features.

One-sentence summary. A Mercer kernel is a similarity function whose Gram matrices are always positive semidefinite, which makes it both an inner product in some feature space (the kernel trick) and a valid covariance for a Gaussian process. You generate kernels from features, from the standard zoo, or by adding, multiplying and exponentiating existing ones, and in a GP the kernel you build is literally the assumption about what the unknown function looks like.
