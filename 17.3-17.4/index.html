17.3–17.4The big picture

Kernel methods predict by comparing a new point to remembered training points. The question in these sections is how many points you have to remember, and whether you get honest probabilities in return.

In 17.3.1–17.3.4 the SVM drew the widest road between two groups. Only a few training points, the support vectors, ended up mattering. That is a nice property: to classify something new you only compare it to those few points. But the plain SVM has four gaps, and the rest of 17.3 patches them one at a time:

17.3.5Converting SVM outputs into probabilities

An SVM gives you a score $f(\mathbf{x})$, not a probability. Platt scaling passes the score through an S-shaped curve whose shape is fitted on held-out data.

Real-world example: a credit-card fraud alarm
A bank scores every transaction by amount and distance from the cardholder's home. The bank has three possible actions: freeze the card (annoying, so only if fraud is very likely), text the customer (cheap, fine at moderate risk), or do nothing. To choose, the bank needs "there is a 72% chance this is fraud." An SVM score of $f = 0.8$ doesn't say that. It only says which side of the road the transaction is on and how far from the center line.

The fix: squash the score with a sigmoid

Platt scaling
$$p(y = 1 \mid \mathbf{x}) \approx \sigma\big(a\,f(\mathbf{x}) + b\big), \qquad \sigma(z) = \frac{1}{1+e^{-z}}$$
In plain English
"Take the SVM's score, stretch it by $a$, shift it by $b$, and squash it into the range 0 to 1." The two numbers $a$ and $b$ are found by ordinary 1D logistic regression: on a separate validation set, choose the $a, b$ that make the observed fraud labels most likely.

Why a separate validation set? On the training set the SVM has pushed points to sit at or beyond its curbs on purpose, so their scores look more confident than they deserve. Fresh data gives an honest picture of how often a score of 0.8 actually turns out to be fraud.

The catch (the book is candid about this): nothing in SVM training makes $f(\mathbf{x})$ behave like a log-odds, so the probabilities can be poorly calibrated. Logistic regression (Chapter 10) gives probabilities directly. Platt scaling is a patch added afterward.

  • Platt scaling: $p \approx \sigma(a f(\mathbf{x}) + b)$, with $a, b$ fitted by logistic regression on a validation set.
  • It works fine in practice but has no deep justification. If you need probabilities from the start, use a probabilistic model.

17.3.6Connection with logistic regression

An SVM and L2-regularized logistic regression solve the same kind of problem. Both minimize "penalty on $\mathbf{w}$ + loss on each point". Only the loss is different, and that difference makes the SVM sparse.

Real-world example: two teachers grading
Students are graded on how far they are past the passing line. Teacher Hinge says: "Clear the bar by a comfortable margin and I stop caring. No extra credit." Teacher Logistic says: "You passed, but I'd like you a little more confident. Every bit helps." Students far above the bar take none of Teacher Hinge's attention. Teacher Logistic gives every student a little.

The SVM, rewritten without constraints

The soft-margin SVM from 17.3.3 can be written as one formula with no constraints. Compare it with logistic regression. Both use the margin $m_n = y_n f(\mathbf{x}_n)$ from before (positive = correct, bigger = safer):

SVM vs. logistic regression
$$\text{SVM:}\ \ \min_{\mathbf{w}}\ \tfrac12\lVert\mathbf{w}\rVert^2 + C\sum_n \underbrace{\max(0,\ 1 - m_n)}_{\text{hinge loss}} \qquad\quad \text{LR:}\ \ \min_{\mathbf{w}}\ \tfrac12\lVert\mathbf{w}\rVert^2 + C\sum_n \underbrace{\log\big(1 + e^{-m_n}\big)}_{\text{log loss}}$$
In plain English
Both say: "keep the weights small, and charge each point for not being confidently correct." The hinge loss charges nothing once a point is past the curb ($m_n \ge 1$). The log loss never quite reaches zero, so it always charges a little.

Both losses are convex upper bounds on the 0-1 loss, the one we actually care about ("1 if wrong, 0 if right"), which is too jagged to optimize directly. They are smooth stand-ins for it. (The book plots the log loss in base 2 so all three curves pass through the same point at $m = 0$. The demo does the same.)

Why the flat part matters

A point's "pull" on the boundary is the slope of its loss. Where the hinge loss is flat, the slope is zero, so the point exerts no pull: that is exactly $\alpha_n = 0$ from 17.3.2. With log loss the slope is never zero, so every point pulls a little. That is why logistic regression gives probabilities but keeps every point, while the SVM keeps few points but gives no probabilities.

Takeaways for 17.3.6

  • SVM = linear model + hinge loss + L2 penalty. Logistic regression = linear model + log loss + L2 penalty.
  • The hinge is exactly zero for $m \ge 1$, so confidently correct points have no pull. This is where the SVM's sparsity comes from.
  • Log loss is never zero, so logistic regression uses every point, but its output is a real probability.

17.3.7Multi-class classification with SVMs

An SVM can only answer yes-or-no questions. To sort into $K$ classes, ask several yes-or-no questions and combine the answers. Both standard ways of combining them leave some regions where the answer is unclear.

Real-world example: a recycling sorter
A conveyor belt carries plastic, glass and metal. A sensor measures each item's weight and how shiny it is. One SVM can only say "this side or that side," so the sorter has to be built from several SVMs.

Two ways to combine yes-or-no SVMs

  • One-vs-rest (OvR, also called one-vs-all): train $K$ SVMs, each asking "is it class $k$, or anything else?" Predict the class that says yes. Problem: sometimes nobody says yes, and sometimes two do. Picking the highest score fixes that, but scores from separately trained SVMs aren't on a common scale. Also, each SVM sees one small class against a big pile of the others, which is lopsided.
  • One-vs-one (OvO): train one SVM for every pair of classes, $K(K-1)/2$ of them, and let them vote. Problem: votes can tie. It also takes many classifiers: 45 for the ten digits 0–9.
One-vs-rest, taking the largest score
$$\hat{y}(\mathbf{x}) = \arg\max_{k}\ f_k(\mathbf{x})$$
In plain English
"Ask each class's SVM how strongly it claims the item, and go with the loudest." It always gives an answer, but there's no guarantee the answers are fair across classes. Compare softmax (multinomial) logistic regression, which handles $K$ classes in a single model with probabilities that add up to 1.

  • SVMs are naturally two-class. Multi-class SVMs are built from several binary ones.
  • One-vs-rest: $K$ classifiers, can leave "nobody" or "conflict" regions; argmax fixes it but compares scores that aren't on a common scale.
  • One-vs-one: $K(K-1)/2$ classifiers and voting, which can tie.
  • Probabilistic models (softmax regression, and the RVM in 17.4) handle many classes directly.

17.3.8How to choose the regularizer $C$

The SVM doesn't choose its own $C$ (or the RBF kernel's $\gamma$). Try a grid of values spaced on a log scale and keep the pair that does best in cross-validation.

Real-world example: a vineyard deciding when to pick
A vineyard labels past grape samples "ready" or "not ready" by sugar level and acidity. The boundary is curvy, and some labels are just wrong (a tired taster). The vineyard wants an RBF SVM, but it needs two settings: how strict to be about mistakes ($C$), and how short each support vector's reach is ($\gamma$). Grading the model on the same samples it trained on would always favor the most wiggly model, so they hold samples out to test on.

The recipe

  1. Standardize each feature (subtract the mean, divide by the standard deviation), so that $\gamma$ means the same thing in every direction.
  2. Pick values on a log scale, such as $C \in \{0.1, 0.3, 1, 3, \dots\}$ and $\gamma \in \{0.01, 0.03, 0.1, \dots\}$. Doubling $C$ matters about as much at $C = 1$ as at $C = 100$, which is why the spacing is multiplicative.
  3. For each pair, run 5-fold cross-validation: train on four-fifths of the data, test on the remaining fifth, rotate, and average.
  4. Keep the best pair and retrain on all the data.
Why both at once?
$C$ and $\gamma$ interact. A large $\gamma$ (short reach) can be partly offset by a small $C$ (lenient), so good settings often form a diagonal ridge in the grid instead of a single spot. Tuning them one at a time can miss that ridge.

Compared to earlier sections: a Gaussian process (17.2) tunes its kernel by maximizing the marginal likelihood, with no held-out data needed. The SVM has no likelihood, so it has to use cross-validation, which means hundreds of training runs. (The book also mentions regularization path algorithms that compute the solution for every $C$ in a single sweep.) The RVM in 17.4 gets back to the GP's approach.

  • $C$ and $\gamma$ are picked from outside the SVM, usually by cross-validation on a log-spaced grid.
  • Standardize features first, and search $C$ and $\gamma$ together, since they trade off against each other.
  • This costs many training runs. Probabilistic models can instead tune hyperparameters by maximizing the marginal likelihood (GP, RVM).

17.3.9Kernel ridge regression

Ridge regression plus the kernel trick gives smooth curves for predicting numbers. The catch: every training point gets a nonzero weight, so you have to keep all of them.

Real-world example: a bike-rental shop
A shop owner wants to predict how many bikes they'll rent from the day's temperature. Cold days are slow, pleasant days are busy, and on scorching days people stay inside. That isn't a straight line, so they use a kernel. The owner keeps a notebook of past days. Kernel ridge regression predicts today by comparing it with every page of that notebook.

From ridge regression to kernel ridge regression

Ridge regression fits $f(\mathbf{x}) = \mathbf{w}^\top\boldsymbol\phi(\mathbf{x})$ with a penalty $\lambda\lVert\mathbf{w}\rVert^2$. As with the SVM dual, the solution can be rewritten so the features only appear through dot products, and those can be swapped for a kernel:

Kernel ridge regression
$$f(\mathbf{x}) = \sum_{n=1}^N \alpha_n\,\mathcal{K}(\mathbf{x}, \mathbf{x}_n), \qquad \boldsymbol\alpha = (\mathbf{K} + \lambda\mathbf{I})^{-1}\mathbf{y}$$
In plain English
"The prediction for a new day is a weighted sum of similarities to every past day." $\mathbf{K}$ is the $N\times N$ table of similarities between training days, and $\lambda$ controls smoothness (bigger = smoother). Solving that linear system gives every past day a weight $\alpha_n$, and in general none of them is exactly zero.

Compared to earlier sections: this is exactly the posterior mean of a Gaussian process (17.2) with noise variance $\lambda$. The GP also gives error bars, which kernel ridge regression doesn't. It is also related to kernel regression (Nadaraya-Watson, 16.3), but here the weights are solved for instead of just being normalized similarities.

Takeaways for 17.3.9

  • $\boldsymbol\alpha = (\mathbf{K} + \lambda\mathbf{I})^{-1}\mathbf{y}$ and $f(\mathbf{x}) = \sum_n \alpha_n\mathcal{K}(\mathbf{x},\mathbf{x}_n)$.
  • The fit is good, but the model is dense: all $N$ training points are needed at prediction time, and training means solving an $N\times N$ system.
  • Same predictions as a GP's posterior mean, without the error bars.

17.3.10SVMs for regression

Swap the squared error for a loss that ignores small mistakes. Every point that lands inside a tube of width $\pm\epsilon$ around the curve gets weight exactly zero, so the model becomes sparse again.

Real-world example: staffing the bike shop
The owner uses the prediction to decide how many staff to schedule. Being off by 30 bikes doesn't change the schedule, but being off by 200 does. So errors smaller than some tolerance $\epsilon$ (here 50 bikes) are free. Only bigger misses cost anything.

The epsilon-insensitive loss

Epsilon-insensitive loss, and the SVR objective
$$L_\epsilon(y, \hat y) = \max\big(0,\ |y - \hat y| - \epsilon\big) \qquad\quad \min_{\mathbf{w}}\ \tfrac12\lVert\mathbf{w}\rVert^2 + C\sum_n L_\epsilon\big(y_n, f(\mathbf{x}_n)\big)$$
In plain English
"Draw a tube of half-width $\epsilon$ around the curve. Points inside the tube cost nothing. Points outside pay by how far they stick out. Keep the curve as flat as possible." This is the same pattern as the hinge loss in 17.3.6: a flat region with zero cost, which gives zero pull.

Going to the dual gives the same structure as before:

SVR prediction
$$f(\mathbf{x}) = \sum_{n} (\alpha_n - \alpha_n^*)\,\mathcal{K}(\mathbf{x}, \mathbf{x}_n) + w_0$$

There are two multipliers per point, $\alpha_n$ for sticking out above the tube and $\alpha_n^*$ for sticking out below, and each is capped at $C$. Points strictly inside the tube have $\alpha_n = \alpha_n^* = 0$. The support vectors are the points on or outside the tube wall.

Takeaways for 17.3.10

  • $\epsilon$-insensitive loss: misses smaller than $\epsilon$ are free. This gives regression a "road" (a tube).
  • Points inside the tube get zero weight, so the model is sparse. Bigger $\epsilon$ gives fewer support vectors and a rougher fit.
  • Like the classification SVM, there are no error bars, and $\epsilon$, $C$ and the kernel width must be chosen by cross-validation.

17.4Sparse vector machines: L1VM and RVM

The SVM gets sparsity as a side effect of its loss. Sparse vector machines ask for sparsity directly: treat "similarity to each training point" as a feature, then fit an ordinary probabilistic model with a prior that pushes most weights to exactly zero.

Real-world example: a realtor's "comps"
To price a house, a realtor doesn't average every sale in the city. They pick a few comparable houses ("comps") and reason from those. Kernel ridge regression is the agent who checks every sale. A sparse vector machine is the realtor who learns which few sales are worth checking, and, in the RVM's case, also says how sure they are ("450 thousand, give or take 20 thousand").

Step 1: turn the kernel into features

Give each training point $\mathbf{x}_n$ its own feature: "how similar is the new input to $\mathbf{x}_n$?" Stack them into one feature vector:

Kernel features
$$\boldsymbol\phi(\mathbf{x}) = \big[\mathcal{K}(\mathbf{x},\mathbf{x}_1),\ \mathcal{K}(\mathbf{x},\mathbf{x}_2),\ \dots,\ \mathcal{K}(\mathbf{x},\mathbf{x}_N)\big], \qquad f(\mathbf{x}) = \mathbf{w}^\top\boldsymbol\phi(\mathbf{x}) = \sum_n w_n\,\mathcal{K}(\mathbf{x},\mathbf{x}_n)$$
In plain English
"Put a little bump on every training point, and predict with a weighted sum of bumps." It looks just like kernel ridge regression, but now $\mathbf{w}$ is the parameter vector of an ordinary generalized linear model. You can attach any likelihood (Gaussian for regression, Bernoulli or softmax for classification) and any prior you like.

A useful bonus: because $\mathcal{K}$ is only being used to build features, it doesn't have to be a valid Mercer kernel (17.1). Any similarity score works. An SVM or a GP can't do that.

17.4.1 Relevance vector machines: how the pruning works

The RVM gives each weight its own "leash" $\alpha_n$: the prior says $w_n \sim \mathcal{N}(0, 1/\alpha_n)$. Instead of picking the $\alpha_n$ by cross-validation, it learns them by maximizing the marginal likelihood (empirical Bayes, the same idea used to tune a GP). Each round alternates two steps:

One RVM update (regression)
$$\boldsymbol\Sigma = \big(\beta\,\boldsymbol\Phi^\top\boldsymbol\Phi + \mathrm{diag}(\boldsymbol\alpha)\big)^{-1},\quad \boldsymbol\mu = \beta\,\boldsymbol\Sigma\boldsymbol\Phi^\top\mathbf{y} \qquad\Longrightarrow\qquad \alpha_n \leftarrow \frac{1 - \alpha_n\Sigma_{nn}}{\mu_n^2}$$
In plain English
"Given the current leashes, find the best weights $\boldsymbol\mu$ and how unsure we are about them, $\boldsymbol\Sigma$. Then tighten the leash on any weight that isn't earning its keep." If a bump is redundant (its neighbors already explain the data), its $\mu_n$ gets small, its $\alpha_n$ shoots to infinity, and the weight is pinned at exactly 0. That training point is pruned. The survivors are called relevance vectors. The noise precision $\beta$ is learned the same way, so the RVM picks its own noise level.

Unlike the SVM, the RVM is fully probabilistic. It gives error bars for regression and real probabilities for classification, and it handles many classes directly with a softmax likelihood. The price: the objective isn't convex, so you can get different answers from different starting points, and a naive implementation costs $O(N^3)$ per round. The L1VM, by contrast, is convex but needs $\lambda$ chosen by cross-validation.

Takeaways for 17.4–17.4.1

  • Use the kernel as features, $\phi_n(\mathbf{x}) = \mathcal{K}(\mathbf{x},\mathbf{x}_n)$, and fit a GLM. Sparsity comes from the prior, not the loss.
  • L1VM = lasso on kernel features: convex, sparse, $\lambda$ chosen by CV.
  • RVM = one learned precision per weight (ARD). Redundant weights get $\alpha_n \to \infty$ and are pruned. It's very sparse, sets its own hyperparameters, and gives probabilities.
  • The kernel doesn't need to be Mercer, and classification with many classes works naturally.

17.4.2Comparison of sparse and dense kernel methods

On the same data, all four methods fit about equally well. What differs is how many training points they keep, whether they give probabilities, and how you set their knobs.

Like the book's comparison figure, this fits four methods with the same RBF kernel to the same noisy data. The L2VM, L1VM and SVR use fixed, sensible settings (in practice you'd tune them by CV). One-paragraph summary. An SVM's score can be turned into a probability with Platt scaling, a sigmoid fitted on held-out data (17.3.5). The SVM is just L2-regularized logistic regression with the log loss swapped for the hinge loss, and the hinge's flat zero region is what makes most training points irrelevant (17.3.6). Several binary SVMs can be combined into a multi-class classifier, at the cost of ambiguous regions (17.3.7), and $C$ and the kernel width must be picked by cross-validation (17.3.8). For regression, kernel ridge regression is accurate but keeps every point (17.3.9). The $\epsilon$-insensitive loss restores sparsity (17.3.10). Sparse vector machines get sparsity from a prior instead: use kernels as features and fit a GLM with an L1 penalty (L1VM) or a learned per-weight precision (RVM), which gives a small model with probabilities (17.4).
