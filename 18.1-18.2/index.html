01 / §18.1.1 · MODEL DEFINITION

A tree is a map of questions.

Imagine a café predicting whether a customer will buy a snack. Each row is a past visit. A tree groups similar visits by asking questions about their features.

18.1–18.3 · ROUTING & PREDICTION
R1 = {x : wait ≤ 3.5}
f(x) = ∑j=1…J wj 𝟙(x ∈ Rj)

Read it: Find the leaf containing this visit, then return that leaf’s prediction wj. The indicator 𝟙 is 1 for the matching leaf and 0 everywhere else. Only one term survives.

R means a region of feature space; J is the number of leaves. For a deeper leaf, combine every condition along its path. For regression, wj is the mean target in that leaf (18.3). For classification, store class proportions and choose the largest one.

What does “partition the input space” look like?

With two features, every question cuts a rectangle horizontally or vertically. Only the rectangle reaching that node is cut. Move the second boundary below; it does not cross the whole space.

Illustrative regions, not a fitted tree: R₁ = {wait ≤ 3.5}; R₂ = {wait > 3.5, party ≤ t}; R₃ = {wait > 3.5, party > t}.

02 / §18.1.2 · MODEL FITTING

Which question makes the cleanest groups?

Try a threshold. Count the buyers in each child. Measure how mixed each group is. Then average those scores, giving bigger groups more weight.

For a numeric feature, test boundaries between sorted unique values. Midpoints give the same training partitions as the lower observed values used in the book. Skip candidates that create an empty child. Exact ties are broken by feature order, then threshold.

18.7–18.9 · MEASURE A GROUP
p̂c = number in class cnumber in this node
Gini = 1 − ∑c p̂c²
Entropy = −∑c p̂c log₂ p̂c

Read it: Estimate each class’s share, then measure the mixture. A pure group has cost 0. A 50/50 binary group has Gini 0.5 or entropy 1 bit.

We write p̂ instead of Murphy’s π̂ic. Entropy uses log₂ here; natural logs rescale all entropy scores by the same positive constant, leaving the best split unchanged. Use 0 log 0 = 0. Gini is the mismatch probability for two independent class draws from this node, rather than the error of its majority prediction.

18.5 · CHOOSE A QUESTION
Q(d,t) = nLn CL + nRn CR
(d*, t*) = arg mind,t Q(d,t)
Gain = Cparent − Q(d,t)

Read it: Try each feature and threshold. Keep the pair with the smallest weighted child cost. Equivalently, maximize the gain.

n is the number reaching this node; nL and nR count its children. C can be Gini, entropy, or regression MSE. Weight by group size: an impure group of 100 should count more than an impure group of 2.

A COMPLETE FIRST SPLIT · GINI

At the root, 4 of 8 visits buy a snack: 1 − (4/8)² − (4/8)² = 0.500. At wait ≤ 3.5, the left child is 3 yes / 0 no, with Gini 0. The right is 1 yes / 4 no, with Gini 0.320.

Q = (3/8) × 0 + (5/8) × 0.320 = 0.200
Gain = 0.500 − 0.200 = 0.300

That is the best root split across both features in our data. A leaf on the right would predict “no,” with an empirical yes probability of 1/5 = 0.20.

18.4 · THE TRAINING OBJECTIVE
L(θ) = ∑n=1…N ℓ(yn, f(xn; θ)) = ∑j=1…J ∑xₙ ∈ Rⱼ ℓ(yn, wj)

Read it: Add the prediction losses across all training visits. Grouping those visits by leaf gives the same total. θ includes the questions, the tree structure, and the leaf predictions.

Searching every possible whole tree is computationally hard. CART uses a greedy search: pick the best next question now. That does not guarantee the best final tree. For classification, Gini and entropy act as useful split criteria; they differ from raw misclassification error.

Why can a greedy split miss a good tree? The XOR example.
0, 0 → no0, 1 → yes1, 0 → yes1, 1 → no

Each feature alone leaves a 50/50 mix, so the first split has zero gain. But two levels of questions can separate all four points perfectly. A procedure that requires positive immediate gain will stop too early. Allowing a zero-gain split followed by more growth can reveal the pattern.

18.3 · FIT A LEAF
wj = ∑xₙ ∈ Rⱼ ynnj

Read it: Add the rental counts in this leaf and divide by how many days reached it. The mean minimizes squared error.

At 17 °C, the cooler group has counts 12, 18, 20, 22. Its prediction is (12 + 18 + 20 + 22)/4 = 18 rentals.

Why the mean?
d/dw ∑(yn − w)² = 2∑(w − yn) = 0
⇒ njw = ∑yn ⇒ w = mean(y)

This smooth calculation fits the leaf value once the region is fixed. The discrete split search still needs candidate questions.

18.6 · SCORE A LEAF
MSE(Di) = ∑n ∈ Dᵢ (yn − ȳi)²ni

Read it: Measure each day’s distance from the leaf mean, square it, and average. Squaring prevents positive and negative errors from cancelling.

The cooler group’s SSE is 36 + 0 + 4 + 16 = 56; its MSE is 56/4 = 14. Minimize the weighted child MSE using the same Q equation as before.

MSE vs. SSE: For a fixed parent with n examples, Q = (SSEL + SSER)/n. Minimizing weighted child MSE therefore picks the same split as minimizing total child SSE. Adding the two child MSEs without size weights can pick the wrong split.

05 / §18.1.3–18.1.5 · PRACTICAL TREES

A perfect memory can be a poor predictor.

Deep trees can chase the quirks of the training data. Use unseen examples to decide how much complexity is useful.

OVERFITTING LAB

A noisier bike-rental example

24 training days and 48 separate validation days, generated with a fixed seed. All depths are actually fitted. Green dots/line: training data/error. Orange line: validation error. These finite-sample curves need not have a perfect U shape. Choose depth using validation or cross-validation; reserve a final test set for evaluation.

A

Stop early

Limit depth or require a minimum number of examples per leaf. Fewer questions usually mean less variance, at the cost of a simpler fit.

B

Prune back

Grow a larger tree, then replace some subtrees with leaves. Compare the resulting trees on validation data. Pruning lets you reconsider choices after seeing deeper splits.

Optional common extension: minimize training loss + α × number of leaves. Larger α prefers smaller trees; tune α by cross-validation.

C

Handle missing features

If wait time is missing, a surrogate split uses another feature that best reproduces the original split’s routing on training data. It is a backup learned at that node.

For categorical inputs, “missing” can also be its own category. These are heuristics, not a full probability model of missingness.

What about categorical features and soft trees?

A categorical question can test “drink type = tea?” versus everything else. This searches categories rather than numeric thresholds. Multiway splits are also possible but may leave very little data in each child.

A soft decision tree replaces a hard yes/no gate with a smooth logistic gate. For a fixed structure, that enables gradient-based fitting. Our labs use ordinary hard, axis-aligned splits.

Why trees are useful

Readable rules; nonlinear interactions; numeric or categorical features; little need to scale numeric features.

Why one tree can struggle

Greedy choices; abrupt boundaries; constant regression predictions; instability when the training set changes. The last issue motivates ensembles.

06 / §18.2 · ENSEMBLE LEARNING

Let several models have a say.

Three bike-shop forecasts say 20, 30, and 40 rentals. Their average is 30. If their errors differ, averaging can cancel some of the noise.

18.10 & 18.12 · AVERAGING / STACKING

Mix three predictions

These controls illustrate a weighted average. Moving them by hand is not training a stacker. In this demo, nonnegative weights are normalized to sum to 1; the general regression stacking formula permits other coefficients.

18.10 · EQUAL AVERAGING → 18.12 · LEARNED COMBINATION
f̄(x) = 1M ∑m=1…M fm(x) → fstack(x) = ∑m=1…M wm fm(x)

Read it: Equal averaging gives every model the same voice. Stacking learns how to combine their predictions. The base models can be trees or different kinds of predictors.

Train the combiner on held-out predictions or out-of-fold predictions. A model’s predictions on its own training rows are too optimistic and can mislead the combiner. Use another test set to evaluate the finished ensemble.

For classification, you can average class probabilities (soft voting) or count predicted class labels (hard voting). These can disagree because probabilities retain confidence information.

18.11 · MAJORITY VOTING

Can weak voters make a strong committee?

Imagine several spam filters, each with the same chance θ of classifying a message correctly. Under independent errors, the number of correct votes S follows a binomial distribution.

P(correct majority) = ∑k=⌊M/2⌋+1…M (M choose k) θk(1−θ)M−k

This is the binomial upper tail, equivalent to 1 − B(M/2, M, θ) in 18.11. Odd M avoids ties. Independence and identical accuracy are assumptions of this calculation, not typical guarantees in real ensembles.

WHY DIVERSITY MATTERS

More copies of the same mistake do not help.

Var(f̄) = σ² [ρ + (1−ρ)/M]

Extra intuition for §18.2: derived by summing variances and covariances, assuming equal individual error variance σ² and common pairwise correlation ρ. The plot uses σ² = 1. At ρ = 0, variance falls as 1/M. At ρ = 1, averaging changes nothing. Averaging equally biased models does not automatically remove their bias.

18.13 · PREDICTIVE ENSEMBLE

Learn a combination

p(y | x, w, θ) = ∑m wm p(y | x, θm)

The aim is a useful combined predictor. Weights can be chosen for predictive performance. When combining probability distributions directly, require wm ≥ 0 and ∑wm = 1 so the result remains a valid distribution.

18.14 · BAYES MODEL AVERAGING

Average over model uncertainty

p(y | x, D) = ∑m p(m | D) p(y | x, m, D)

The weights are posterior model probabilities, derived from priors and evidence. Each model’s predictive distribution also averages its parameter uncertainty.

Similar-looking sums have different meanings. Under suitable identifiability and posterior-consistency conditions, BMA can concentrate on one model as data increase. That is not a universal guarantee, and predictive ensembling need not select one model.

KEEP THIS MENTAL CHECKLIST

To build a tree…

  1. Start with the rows at this node. Not the entire dataset again.
  2. Try feature–threshold pairs. Send ≤ left and > right.
  3. Fit a value in each child. Class proportions or a target mean.
  4. Score the split. Use the size-weighted child costs.
  5. Keep the smallest score and recurse. Stop or prune to control complexity.
  6. To ensemble, combine predictions. Diverse errors help; validation keeps the comparison honest.
