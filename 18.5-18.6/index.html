01 / §18.5.5–18.5.5.1 · GRADIENT BOOSTING

Fit the next tree to the slope of the loss, not the raw residual.

In §18.5.2, least-squares boosting fit each new tree to the residuals y − f(x). That trick only works for squared loss. Gradient boosting works for any differentiable loss: each new tree is fit to the negative gradient of the loss at every training point, called the pseudo-residual. It is gradient descent, where each step is a small tree.

Why would you want a different loss? Say you predict house prices from size. Five listings have typos that overstate the price by about $650k. Squared loss lets each typo pull on the model with a force proportional to its error. A robust loss caps that pull.

ONE ROUND OF GRADIENT TREE BOOSTING
1. r̃i = −∂ℓ(yi, f)∂f at f = fm−1(xi)
2. fit a regression tree to {(xi, r̃i)} → leaf regions Rj
3. wj = argminw ∑i∈Rj ℓ(yi, fm−1(xi) + w)
4. fm(x) = fm−1(x) + ν·wj(x)

Step 2 uses the gradient only to decide where to split. Step 3 then picks each leaf's value using the real loss: the mean residual for squared loss, the median residual for absolute loss.

THE LOSS DECIDES WHAT “RESIDUAL” MEANS
Loss ℓ(y, f)Pseudo-residual −∂ℓ/∂f

Log loss, y ∈ {0,1}y − σ(f)

Huber here uses δ = $60k. Stochastic gradient boosting adds one twist: fit each tree on a random subsample of the rows (often half). It is faster and usually generalizes better.

02 / §18.5.5.2 · XGBOOST

XGBoost: gradient boosting that penalizes complicated trees.

XGBoost (“extreme gradient boosting”) is one of the most popular libraries for tabular data and a regular winner of data-science competitions. It changes two things. It adds a penalty for tree complexity to the objective, and it uses the second derivative of the loss as well as the first. Together these give closed-form answers for each leaf's value and for whether a split is worth making.

Here a spam filter is growing its first tree. Every email starts at p(spam) = 0.5. Should the tree split on “does the email contain the word hp?”

THE REGULARIZED OBJECTIVE
ℒ = ∑i ℓ(yi, f(xi)) + Ω(f)
Ω(f) = γJ + ½λ ∑j=1J wj²

J is the number of leaves and wj are the leaf values. γ charges for every leaf; λ discourages extreme leaf values. Expanding the loss to second order around the current model gives each email a gradient gi and a curvature hi. For log loss, gi = pi − yi and hi = pi(1 − pi).

CLOSED-FORM LEAVES AND SPLITS
wj* = −GjHj + λ,   Gj = ∑i∈leaf gi, Hj = ∑ hi
gain = ½ [ GL²HL+λ + GR²HR+λ − (GL+GR)²HL+HR+λ ] − γ

Split only if the gain is positive. That gain number matters again in a moment: adding it up per feature is how feature importance is computed.

03 / §18.6.1 · FEATURE IMPORTANCE

Which inputs matter? Add up the gain from every split that used them.

We trained a 200-tree boosted spam filter on 1,200 emails. Each email is described by how often nine words or characters appear, modeled on the UCI spambase data the book uses. That data came from emails at HP Labs, so the words hp and george (the person who collected it) are strong signs of a non-spam work email. We also slipped in one input that is pure noise: a random digit from the message ID.

Every time a tree splits on a feature, that split reduces the loss by some amount (its gain). A feature's importance is the total gain from all splits on it, summed over all trees. The top feature is scaled to 100.

What importance does not tell you

  • Direction. “hp” and “!” both rank high, but one points toward ham and the other toward spam. You need section 04 for that.
  • Credit is shared between look-alikes. Tick the checkbox. Nothing about the emails changes, yet “!” drops sharply because a near-copy now takes some of the splits. Add the twins' scores together to judge the underlying signal.
  • Cause. It ranks what the model uses, not what causes spam.
THE FORMULA
Rk(T) = ∑j = 1J−1 Gj · 𝟙(vj = k),     Rk = 1M ∑m=1M Rk(Tm)

The sum runs over the J − 1 internal (splitting) nodes of tree T; vj is the feature node j splits on and Gj is the gain (drop in loss) from that split. Average over the trees, then rescale so the largest is 100. Averaging over many trees makes the ranking much more reliable than reading a single tree.

04 / §18.6.2 · PARTIAL DEPENDENCE PLOTS

How does the prediction move as one input changes?

Pick a feature, say the frequency of “!”. Pretend every email in the data set had “!” at exactly 0.3%, leaving every other word as it was. Run all of them through the model and average the predicted spam probability. Repeat for a range of values. That curve is the partial dependence of the model on “!”: its effect with the other features averaged out.

TWO FEATURES AT ONCE
THE FORMULA
f̄k(xk) = 1N ∑n=1N f(xk, xn,−k)

xn,−k means email n's values for every feature except k. So we sweep feature k while keeping each email's other features as they really are. The grey lines are those individual sweeps; the colored line is their average.

Interactions. The same idea works for a pair of features. With “!” across and “hp” up, the map shows that “!” raises the spam probability a lot for emails without “hp”, but much less for work emails that mention hp. A one-feature plot averages that difference away.

Caveat: if features are strongly correlated, the sweep invents unrealistic emails (lots of “$” but no other money words), so read the edges of the plot with care.

Check yourself

For absolute loss, what is each pseudo-residual, and why does that make the model robust to typos?

sign(y − f), so every point is ±1. A listing that is $650k too high pulls on the next tree exactly as hard as one that is $5k too high. With squared loss the pull is proportional to the error.

In XGBoost, a leaf holds 2 emails, both spam, and every email currently has p = 0.5. What is its weight with λ = 0 and with λ = 1?

g = 0.5 − 1 = −0.5 each, so G = −1. h = 0.25 each, so H = 0.5. w* = −G/(H + λ) = 2 with λ = 0, and 1/1.5 ≈ 0.67 with λ = 1. λ shrinks small leaves the most.

The noise digit gets a small but nonzero importance. Why not exactly zero?

With enough trees, a few splits on noise will happen to reduce the training loss slightly by chance. Gain-based importance is measured on training data, so it gives those lucky splits a bit of credit.

Two features are near-copies. Each gets importance 50. What can you conclude?

That the shared signal they carry is important, roughly on par with a single feature scoring about 100. Removing one copy would probably hurt the model very little, since the other could take over.

The partial dependence on “!” is nearly flat for one subgroup of emails and steep for another. Where would you see that?

In the individual (ICE) lines fanning out, or in a two-feature partial dependence plot such as “!” against “hp”. The single averaged curve would hide it.
