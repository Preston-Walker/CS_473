RANDOM FORESTS & BOOSTING

A crowd,
or a coach?

Both methods build one strong predictor out of many decision trees. They do it in opposite ways.

  • Random forest grows lots of deep trees at the same time, each on a shuffled view of the data, and lets them vote.
  • Boosting grows tiny trees one after another. Each new tree focuses on the mistakes the team is still making.

Every chart below is live. The data are synthetic, but each example is modeled on a real use: loan approval, bike-share demand, and spam filtering.

01 / §18.3–18.4 · BAGGING → RANDOM FORESTS

One tree memorizes. A forest averages.

A bank wants to predict whether a loan applicant will repay or default, using two numbers: credit score and debt-to-income ratio. We have 220 past applicants.

A single deep tree draws a jagged, overconfident map that chases every noisy applicant. Now give each tree a bootstrap sample: draw 220 applicants with replacement, so some show up twice and others are left out. Each tree makes different mistakes, and averaging their votes cancels much of that noise.

f(x) = 1M ∑m=1M fm(x)

Tree m is fit to its own bootstrap sample of the data. Averaging lowers variance without adding much bias, which is why the trees are allowed to grow deep.

02 / §18.4 · DECORRELATING THE TREES

If every tree asks the same first question, the crowd thinks alike.

Bootstrap samples overlap a lot. When one feature is very strong (here, credit score), almost every bagged tree splits on it first and ends up looking much like its neighbors. Averaging near-copies doesn't help much, just as polling 50 weather forecasters adds little if they all read the same computer model.

A random forest considers only a random subset of mtry features at each split. Sometimes credit score isn't on the menu, so a tree has to use other evidence. Each tree gets slightly worse, but their errors become less related, and the average gets better.

WHY CORRELATION MATTERS
Var[average of M trees] = ρσ² + 1 − ρMσ²

Each tree's prediction has variance σ², and any two trees have correlation ρ. Adding trees shrinks only the second term. The first term, ρσ², is a floor that no number of trees can get below. Random features lower ρ, which lowers that floor.

This standard identity (Hastie, Tibshirani & Friedman, ESL §15.2) is the usual explanation behind the random-forest idea in §18.4.

03 / §18.5–18.5.1 · FORWARD STAGEWISE ADDITIVE MODELING

Boosting: a sequence of weak learners, each fixing the last.

Think of editing an essay in passes. The first editor fixes the biggest problems. The next one reads the revised draft and fixes what's still wrong, and so on. No single editor needs to be brilliant. Boosting does the same thing with weak learners, usually stumps (one-split trees) or very shallow trees.

THE MODEL · A WEIGHTED SUM
f(x) = ∑m=1M βm Fm(x)

Fm is a small tree and βm is how much we trust it. Unlike a forest, the trees are added, not averaged, and each depends on the ones before it.

THE GREEDY RECIPE · ONE TREE AT A TIME
(βm, θm) = argminβ, θ ∑i ℓ(yi, fm−1(xi) + β F(xi; θ))
fm(x) = fm−1(x) + ν βm F(x; θm)

Freeze everything learned so far, then find the single best tree to add. The learning rate 0 < ν ≤ 1 (shrinkage) takes only part of each step, which usually generalizes better. Choosing the loss ℓ gives the different algorithms below.

Squared loss→ least-squares boosting§04
Exponential loss→ AdaBoost§05

04 / §18.5.2 · QUADRATIC LOSS AND LEAST-SQUARES BOOSTING

With squared loss, every new tree just fits what's left over.

A bike-share company predicts daily rentals from the temperature. Rentals peak on mild days and drop on freezing or scorching ones. Plug squared loss into the recipe and something simple falls out: the best next tree is the one that best predicts the residuals, the part of the data the current model still gets wrong.

WHY THE LOSS TURNS INTO “FIT THE RESIDUALS”
ℓ(y, fm−1(x) + βF(x)) = (r − βF(x))², where r = y − fm−1(x)

Squared error on the original targets equals squared error of the new tree against the residuals ri. So each round is an ordinary regression-tree fit with the residuals as the targets (β can be absorbed into the tree's leaf values). This is least-squares boosting.

05 / §18.5.3 · EXPONENTIAL LOSS AND ADABOOST

AdaBoost: re-weight the emails you keep getting wrong.

Now a classification problem. A mail filter labels emails as spam (ỹ = +1) or ham (ỹ = −1) from two clues: the number of links and the percentage of CAPITAL letters. Each weak learner is a single yes/no rule such as “links > 4.3”.

After each round, AdaBoost raises the weight of every email the team misclassifies and lowers the weight of the rest. The next stump is trained to minimize weighted error, so it is pushed toward the hard cases. Dot size shows weight.

THE LOSS · AND WHERE THE WEIGHTS COME FROM
ℓ(ỹ, f) = exp(−ỹ f)
ℓ(ỹi, fm−1 + βF) = exp(−ỹi fm−1(xi)) · exp(−β ỹi F(xi))
wi,m: fixed by the earlier rounds

The margin ỹf is positive when the email is classified correctly. The part of the loss that earlier rounds have already fixed acts as a weight on each email: emails with a large negative margin get exponentially large weights.

ONE ROUND OF ADABOOST
Fm = argminF ∑ wi,m 𝟙(ỹi ≠ F(xi))
errm = ∑ wi,m 𝟙(ỹi ≠ Fm(xi))∑ wi,m
βm = ½ log 1 − errmerrm
wi,m+1 = wi,m · e−βm ỹi Fm(xi)

An accurate stump (small err) gets a big β. Misclassified emails are multiplied by eβ and correct ones by e−β. The book's Algorithm 18.2 writes the same thing with α = 2β, rescaling only the misclassified emails by eα.

06 / §18.5.4 · LOG LOSS AND LOGITBOOST

LogitBoost: same idea, gentler punishment.

Exponential loss has two drawbacks. It explodes for badly wrong examples, so a few mislabeled emails can take over training, as you just saw. And it isn't the log-likelihood of any probability model, so its scores aren't calibrated probabilities. The fix is to boost the log loss (logistic loss) instead. Its penalty grows only linearly for confident mistakes.

Drag the margin left, toward a confidently wrong example. At −3 the exponential penalty is about 20, while log loss is about 9 and rising only in a straight line.

LOGITBOOST · NEWTON STEPS ON LOG LOSS
ℓ(ỹ, f) = log(1 + e−2ỹf),   p(x) = σ(2f(x))
zi = yi* − pipi(1 − pi),   wi = pi(1 − pi)
Fm = argminF ∑ wi(zi − F(xi))²
f ← f + ½ Fm

Here y* ∈ {0, 1}. Each round fits a regression stump to a working response z with weights w, which is one Newton step on the log loss. Because f is a log-odds score, p(x) is an honest probability.

Why it resists outliers: the weight w = p(1 − p) is largest for emails near the boundary. An email the model confidently gets wrong has p close to 0 or 1, so its weight is tiny. Its pull on the next stump, w·z = y* − p, can never exceed 1. Flip the spam lab to LogitBoost: the big dots move to the boundary, and the ringed emails stay small.

Check yourself

Why can't we just bag 10,000 trees and drive the error to zero?

Averaging only removes the variance the trees don't share. The ρσ² term stays no matter how large M gets, and bias is untouched. Random features lower ρ, which lowers that floor.

Lowering mtry makes each tree worse. Why can the forest get better?

Weaker but less correlated trees can average to a better ensemble. In the feature lab, a single tree's accuracy falls slightly as mtry drops, but ρ falls more and the forest's accuracy rises.

In least-squares boosting, what is the next tree trained to predict?

The current residuals yi − fm−1(xi). Squared error on y with the old model held fixed equals squared error of the new tree against the residuals.

A stump has weighted error 0.5. What is its β, and why?

β = ½ log(0.5 / 0.5) = 0. A coin-flip learner gets no vote. If err > 0.5, β is negative, which means flipping the stump's answers.

Why is LogitBoost more robust to mislabeled data than AdaBoost?

Exponential loss (and so AdaBoost's weights) grows exponentially as the margin becomes negative. Log loss grows only linearly, so each example's pull on the next learner is bounded by 1. Log loss also gives calibrated probabilities through p = σ(2f).
