16.1 → 16.2Why learn a distance at all?

A nearest-neighbor classifier is only as good as its idea of "near".

Section 16.1 builds the K-nearest-neighbor (KNN) classifier: to label a new point, find the $K$ training points closest to it and let them vote. It has no parameters to train. All of its "knowledge" lives in two things: the stored examples, and the distance function $d(\mathbf{x}, \mathbf{x}')$ that decides who counts as a neighbor.

The default choice, Euclidean distance on the raw inputs, treats every feature as equally important. That breaks easily:

  • Irrelevant or noisy features add random amounts to every distance and drown out the features that matter. This is part of the curse of dimensionality from §16.1.2.
  • Raw pixels are a terrible space for distances. Two photos of the same face under different lighting can be farther apart, pixel by pixel, than photos of two different people.

Section 16.2 fixes this by learning the distance from labeled data. The classic form is the Mahalanobis distance, which is just Euclidean distance after a linear map $\mathbf{W}$:

Mahalanobis distance
$$d_{\mathbf{M}}(\mathbf{x}, \mathbf{x}') = \sqrt{(\mathbf{x}-\mathbf{x}')^{\mathsf T}\mathbf{M}(\mathbf{x}-\mathbf{x}')}, \qquad \mathbf{M} = \mathbf{W}^{\mathsf T}\mathbf{W} \succeq 0 \;\Rightarrow\; d_{\mathbf{M}}(\mathbf{x}, \mathbf{x}') = \lVert \mathbf{W}\mathbf{x} - \mathbf{W}\mathbf{x}' \rVert_2$$

The deep version replaces the linear map with a neural network $f_\theta$ and measures distance between embeddings $\mathbf{e} = f_\theta(\mathbf{x})$. Once you have a good embedding, you can use it for KNN classification, retrieval ("find similar products"), verification ("are these the same person?"), clustering, and the open-set recognition problem from §16.1.4: recognizing classes you never saw in training. That last one is where metric learning beats an ordinary classifier. A softmax over $C$ fixed classes can't say "this is a new person". A distance can still say "this face matches the one photo we enrolled yesterday".

Part 1 · Linear metric learning

Learn a single matrix $\mathbf{W}$ (equivalently $\mathbf{M}=\mathbf{W}^{\mathsf T}\mathbf{W}$). This is the shallow ancestor of every network below.

16.2.1LMNN, NCA and LCA

Three ways to turn "neighbors should share labels" into an objective.

Large margin nearest neighbors (LMNN)

For each point $i$, pick a few target neighbors $N_i$. These are the $k$ closest points with the same label, chosen once using plain Euclidean distance. Then ask for two things:

  • Pull: target neighbors should be close.
  • Push: any point of a different class must be at least a margin $m$ farther away than every target neighbor. Points that break this rule are called impostors.
LMNN objective
$$\mathcal{L}(\mathbf{M}) = (1-\lambda)\underbrace{\sum_i \sum_{j \in N_i} d_\mathbf{M}(\mathbf{x}_i,\mathbf{x}_j)^2}_{\text{pull}} + \lambda \underbrace{\sum_i\sum_{j\in N_i}\sum_{l} \mathbb{I}(y_l \ne y_i)\big[m + d_\mathbf{M}(\mathbf{x}_i,\mathbf{x}_j)^2 - d_\mathbf{M}(\mathbf{x}_i,\mathbf{x}_l)^2\big]_+}_{\text{push (hinge on impostors)}}$$

Squared Mahalanobis distances are linear in $\mathbf{M}$, and the hinge $[\cdot]_+$ is convex. So the objective is convex in $\mathbf{M}$ over the convex set of PSD matrices, and you can solve it exactly with semidefinite programming. If you write $\mathbf{M}=\mathbf{W}^{\mathsf T}\mathbf{W}$ and run gradient descent on $\mathbf{W}$, you lose convexity. In return you get unconstrained optimization and can make $\mathbf{W}$ rectangular to get a low-dimensional embedding. Notice the push term already compares an (anchor, same-class, different-class) triple. That is the triplet loss in disguise.

Neighborhood components analysis (NCA)

NCA replaces "the nearest neighbor" with a soft nearest neighbor. Point $i$ picks neighbor $j$ at random, with a softmax over negative squared distances in the projected space:

Stochastic neighbor and expected accuracy
$$p^{\mathbf{W}}_{ij} = \frac{\exp(-\lVert \mathbf{W}\mathbf{x}_i - \mathbf{W}\mathbf{x}_j\rVert^2)}{\sum_{l\ne i}\exp(-\lVert \mathbf{W}\mathbf{x}_i - \mathbf{W}\mathbf{x}_l\rVert^2)}, \qquad J(\mathbf{W}) = \sum_{i}\sum_{j \ne i:\, y_j = y_i} p^{\mathbf{W}}_{ij}$$

$J(\mathbf{W})$ is the expected number of points correctly classified by this randomized 1-NN rule. NCA minimizes $\mathcal{L}(\mathbf{W}) = 1 - J(\mathbf{W})/N$ by gradient descent. The objective is smooth but not convex. Keep it in mind: a softmax over distances, where the "right answers" are the same-class points, comes back as the N-pair and Proxy-NCA losses.

Latent coincidence analysis (LCA)

LCA is the probabilistic cousin. It is trained on pairs labeled similar/dissimilar instead of class labels. Each input gets a noisy latent code $\mathbf{z} \sim \mathcal{N}(\mathbf{W}\mathbf{x}, \sigma^2\mathbf{I})$. Two inputs are "similar" if their latent codes coincide, meaning they land within a small radius of each other. Integrating out the noise gives a match probability that decays like a Gaussian in the projected distance $\lVert \mathbf{W}\mathbf{x} - \mathbf{W}\mathbf{x}'\rVert$. You fit $\mathbf{W}$ (and the noise level) with EM. The noise makes it more tolerant of mislabeled pairs than a hard hinge would be.

Part 2 · Deep metric learning

Replace $\mathbf{W}\mathbf{x}$ with a neural network. The real design choice is what kind of tuple the network sees at each training step.

16.2.2Embedding networks and the unit sphere

Learn $\mathbf{e} = f_\theta(\mathbf{x})$ so that plain Euclidean distance between embeddings means "semantic distance".

For images, audio or text, no linear $\mathbf{W}$ on raw inputs can capture "same identity". So we learn a deep network $f_\theta:\mathcal{X}\to\mathbb{R}^L$, often a CNN or transformer with the classification head removed, and define $d_\theta(\mathbf{x}, \mathbf{x}') = \lVert f_\theta(\mathbf{x}) - f_\theta(\mathbf{x}')\rVert$.

Almost every modern method L2-normalizes the embedding, $\hat{\mathbf{e}} = \mathbf{e}/\lVert\mathbf{e}\rVert$, so all embeddings live on the unit hypersphere. Then distance and cosine similarity carry the same information:

Distance on the sphere
$$\lVert \hat{\mathbf{e}} - \hat{\mathbf{e}}'\rVert^2 = \underbrace{\lVert\hat{\mathbf{e}}\rVert^2}_{1} + \underbrace{\lVert\hat{\mathbf{e}}'\rVert^2}_{1} - 2\,\hat{\mathbf{e}}^{\mathsf T}\hat{\mathbf{e}}' = 2\big(1 - \cos\angle(\mathbf{e}, \mathbf{e}')\big)$$

Why normalize? (1) Distances are bounded in $[0, 2]$, so a margin like $m=0.5$ means the same thing throughout training. (2) The network can't "cheat" a margin-based loss by scaling every embedding up, which makes all the gaps bigger without making the embedding any better. (3) Retrieval reduces to maximum inner product search, which has fast approximate algorithms.

All networks below share one idea. The same network $f_\theta$ (shared weights) is applied to every element of a tuple, and the loss compares the resulting embeddings. They differ in the tuple and the loss.

The original deep metric learning network (Chopra, Hadsell & LeCun, 2005). It has two copies of $f_\theta$ with tied weights, so it is really one network run twice. Same-class pairs are pulled together like a spring. Different-class pairs are pushed apart, but only until they are a margin $m$ apart:

$$\mathcal{L}(\theta;\mathbf{x}_i,\mathbf{x}_j) = \mathbb{I}(y_i = y_j)\, d_\theta(\mathbf{x}_i,\mathbf{x}_j)^2 + \mathbb{I}(y_i \neq y_j)\,\big[m - d_\theta(\mathbf{x}_i,\mathbf{x}_j)\big]_+^2$$

Weakness: it asks for absolute distances (positives at 0, negatives beyond $m$) for every class, even though classes really vary in how spread out they are. The triplet loss only asks for relative order.

Three tied copies of $f_\theta$ (popularized by FaceNet, Schroff et al. 2015). The loss only asks that the anchor be closer to the positive than to the negative, by a margin:

$$\mathcal{L}(\theta;\mathbf{x}_i,\mathbf{x}_i^+,\mathbf{x}_i^-) = \big[d_\theta(\mathbf{x}_i,\mathbf{x}_i^+)^2 - d_\theta(\mathbf{x}_i,\mathbf{x}_i^-)^2 + m\big]_+$$

Relative constraints let a tight class and a loose class coexist. The price is that the number of possible triplets is cubic, and most of them already satisfy the margin and contribute zero gradient. That is why mining matters.

The triplet loss looks at one negative at a time. The N-pair loss (Sohn, 2016) compares the anchor against many negatives at once using a softmax over similarities:

$$\mathcal{L} = -\log\frac{\exp(\mathbf{e}_i^{\mathsf T}\mathbf{e}_i^+)}{\exp(\mathbf{e}_i^{\mathsf T}\mathbf{e}_i^+) + \sum_{k=1}^{N-1}\exp(\mathbf{e}_i^{\mathsf T}\mathbf{e}_k^-)} = \log\Big(1 + \sum_{k=1}^{N-1}\exp\big(\mathbf{e}_i^{\mathsf T}\mathbf{e}_k^- - \mathbf{e}_i^{\mathsf T}\mathbf{e}_i^+\big)\Big)$$

Batching trick: take $N$ (anchor, positive) pairs from $N$ different classes. Every other pair's positive then serves as a negative for free, so $2N$ forward passes give $N^2$ comparisons. With $N=2$ it reduces to $\log(1+e^{\mathbf{e}^{\mathsf T}\mathbf{e}^- - \mathbf{e}^{\mathsf T}\mathbf{e}^+})$, a smooth triplet loss with no margin. With normalized embeddings and a temperature this is the InfoNCE loss used in self-supervised contrastive learning.

The simplest option: train an ordinary $C$-way classifier, then throw away the final layer and use the penultimate features as the embedding. Each class has a weight vector $\mathbf{w}_c$, and the logit $\mathbf{w}_c^{\mathsf T}\mathbf{e}$ already measures similarity between the embedding and a class "template". Normalizing both $\mathbf{e}$ and $\mathbf{w}_c$ (cosine-softmax) turns this into a direct angular metric. Margin variants of that idea (for example the ArcFace family) are a strong baseline for faces.

Cost is linear in $N$, and there are no tuples to sample. The catch is that the objective is about separating these $C$ classes, not about distances directly. Embeddings of unseen classes are often good, but nothing in the loss guarantees it.

Proxy-NCA (Movshovitz-Attias et al., 2017) keeps the metric loss but replaces the other data points with one learnable proxy vector $\mathbf{p}_c$ per class. A proxy is a stand-in for "where class $c$ lives". The NCA softmax is then computed against the $C$ proxies instead of all $N$ points:

$$\mathcal{L}(\mathbf{x}, y) = -\log\frac{\exp\big(-d(\mathbf{e}, \mathbf{p}_y)\big)}{\sum_{c\ne y}\exp\big(-d(\mathbf{e}, \mathbf{p}_c)\big)}$$

This turns an $O(N^3)$ triplet problem into an $O(NC)$ one. You can bound the triplet loss by the proxy loss, so making proxies tight also makes the triplets tight. The "optimize an upper bound" method of §16.2.5.3 (Do et al., 2019) uses the same idea with class centroids in place of learned proxies.

16.2.4.1Siamese networks: the contrastive loss as springs

Positives feel a spring pulling them to zero. Negatives feel a spring that only works inside radius $m$.

Take the gradient of each term with respect to the distance $d$. A positive pair gets $\partial/\partial d\,[d^2] = 2d$, a pull that grows with distance and never switches off. A negative pair gets $-2(m-d)$ while $d < m$ and exactly zero once $d \ge m$. Negatives that are already far enough away contribute nothing. Most random negative pairs are like that after a little training, so a Siamese network trained on random pairs wastes most of its compute.

16.2.4.2 & 16.2.5.1Triplet networks and easy / semi-hard / hard negatives

Fix the anchor and the positive. Where the negative sits decides whether it teaches anything.

Take an anchor $a$ and positive $p$. The negative $n$ falls into one of three zones around the anchor, which the chapter illustrates the same way:

  • hard $d(a,n) < d(a,p)$: the negative is closer than the positive, so the order is wrong. These give the largest gradient. But the very hardest ones are often mislabeled or ambiguous, and training on only them early on can collapse the embedding.
  • semi-hard $d(a,p) \le d(a,n) < \sqrt{d(a,p)^2 + m}$: the order is right but inside the margin, so the loss is still positive. FaceNet trained on these. They give useful, stable gradients.
  • easy beyond the margin: the loss is zero and the gradient is zero. Nearly all random triplets end up here.

The gradient of the triplet loss (when it is active) is a three-way tug: $\partial\mathcal{L}/\partial\mathbf{e}_p = -2(\mathbf{e}_a - \mathbf{e}_p)$ pulls $p$ toward $a$, $\partial\mathcal{L}/\partial\mathbf{e}_n = 2(\mathbf{e}_a-\mathbf{e}_n)$ pushes $n$ away from $a$, and the anchor moves toward $p$ and away from $n$.

16.2.4.3N-pair networks: one positive against many negatives

A softmax over similarities lets the hardest negatives claim most of the gradient by themselves.

Differentiate the N-pair loss with respect to the anchor embedding. Write $q_j$ for the softmax probability the loss assigns to candidate $j$ (the positive or one of the negatives):

$$\frac{\partial \mathcal{L}}{\partial \mathbf{e}_a} = s\Big(\sum_{j} q_j\, \mathbf{e}_j - \mathbf{e}^+\Big) \quad\Longrightarrow\quad -\nabla = s\Big(\underbrace{(1-q_+)\,\mathbf{e}^+}_{\text{pull to positive}} - \underbrace{\textstyle\sum_{k} q_k\, \mathbf{e}_k^-}_{\text{push from negatives, weighted by } q_k}\Big)$$

Each negative pushes in proportion to its probability $q_k$, and that probability is largest for the negatives most similar to the anchor. So the loss mines hard negatives on its own, softly, within every batch. Here $s$ is an inverse temperature, used when embeddings are normalized: larger $s$ means a sharper softmax and more focus on the single hardest negative.

16.2.5Speeding up ranking losses: mining, proxies, upper bounds

Pair and triplet losses are defined over a combinatorial number of tuples. Three fixes.
  1. Mining (§16.2.5.1). Don't sample tuples at random. Look for the informative ones, usually inside each mini-batch to keep it cheap. Hard mining takes the closest negative (and farthest positive) per anchor. Semi-hard mining takes negatives inside the margin but farther than the positive. Semi-hard is safer early in training.
  2. Proxies (§16.2.5.2). Compare each point to $C$ learned class proxies instead of to other points. The cost drops from $O(N^3)$ to $O(NC)$, and no mining is needed.
  3. Optimize an upper bound (§16.2.5.3). Bound the triplet loss by terms that involve class centroids. These are cheap to compute, also $O(NC)$, and minimizing the bound pushes the true triplet loss down too.

Experiments to try
  1. Mining. Pick Triplet + Random and train. Within a few dozen steps the gray "active triplets" curve drops below about 10%. More than 9 of every 10 random triplets are already easy, so most of each batch contributes zero gradient. Re-initialize, switch to Semi-hard, and compare Recall@1 at the same early step count. In our runs semi-hard was ahead after about 60 steps (98% vs. 86%). This toy problem is easy, so both get there eventually. On real datasets with millions of mostly easy triplets the gap is much larger.
  2. Hardest negatives. Try Hardest (batch-hard) with the default settings. In our runs it got stuck near 40–50% Recall@1, with 100% of random triplets still violating the margin. The classes collapse into a tangle instead of separating. Early on, every point's hardest negative sits right on top of it, and pushing against those fights the pull from the positives. That is the collapse FaceNet warned about and the reason semi-hard became the default.
  3. Normalization. Turn normalization off and compare the two ranking losses. Watch the axis-span label in the embedding panel. With Triplet the embedding keeps growing (to about ±8 in our runs), because scaling everything up makes every gap larger relative to a fixed margin. That is a "free" way to reduce the loss. With Contrastive it stays small (about ±1.6), because the absolute targets (positives at 0, negatives at $m$) pin the scale.
  4. Proxies and classifiers. Proxy-NCA and Classification train fast with no mining. Proxies appear as large outlined markers on the circle, and classifier weight directions as dashed rays. Their cost per step is linear in the batch size.
  5. Open set. Hold out class E and train each loss. Losses that only separate the four training classes may squeeze E into a neighbor's region. Compare the two Recall@1 tiles.

16.2.6Other training tricks, and a reality check

The details that decide whether any of the above works in practice.
  • Normalize the embedding (put it on the sphere). This is nearly universal, for the reasons in §16.2.2. A related idea encourages all embeddings to have similar norms before normalization, a "spherical embedding constraint", so the angular distances behave consistently.
  • Start from a pretrained backbone. Most image metric learning fine-tunes an ImageNet-pretrained CNN. The pretrained features already put semantically similar images somewhat close.
  • Batch construction matters. In-batch mining needs several examples per class in each batch. Samplers draw $P$ classes $\times$ $K$ images each, which is exactly what the playground does with $K=6$ for the pair and triplet losses.
  • Evaluate on unseen classes. Standard benchmarks (birds, cars, products) split by class: you train on half the classes and test retrieval on the other half. Only that setup tests the open-set promise.
  • Be skeptical of leaderboard gains. Musgrave et al. (2020, "A Metric Learning Reality Check") re-ran many published losses with the same backbone, embedding size, augmentation and tuning budget. Most claimed improvements over the classic contrastive and triplet losses shrank to almost nothing. A well-tuned simple loss is a strong baseline.
