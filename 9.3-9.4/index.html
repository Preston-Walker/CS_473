The big idea: two ways to answer “which class is this?”

One model learns what each class looks like. The other only learns where the line between them is.

Suppose a fish-processing plant wants a camera to sort salmon from sea bass on a conveyor belt. The camera measures two features for each fish: its length and the lightness of its scales. There are two quite different ways to build the sorter.

Generative: “learn what each class looks like”

Build a full description of each species, $p(\boldsymbol{x}\mid y)$: how long salmon tend to be, how light they are, and how those two features vary together. Do the same for sea bass, and also learn how common each species is, $p(y)$. To classify a new fish, ask which species' description fits this fish better, using Bayes' rule.

It's like an art student who has learned to draw both fish. Because the model describes the inputs themselves, it can generate new, realistic fish. That is where the name comes from.

Discriminative: “learn only the difference”

Skip describing the fish. Learn $p(y\mid\boldsymbol{x})$ directly: a function that takes (length, lightness) and returns the probability of each species. Training only cares about getting the labels right, so the model only has to learn where the boundary is.

It's like an inspector who can't draw either fish but has become very good at the one question “salmon or bass?” It has no idea what a typical fish looks like, so it can't generate one.

Generative classifier: model the joint, then flip it with Bayes' rule
$$p(y=c\mid\boldsymbol{x},\boldsymbol\theta)=\frac{p(\boldsymbol{x}\mid y=c,\boldsymbol\theta)\,p(y=c\mid\boldsymbol\theta)}{\sum_{c'}p(\boldsymbol{x}\mid y=c',\boldsymbol\theta)\,p(y=c'\mid\boldsymbol\theta)}$$
Examples: Gaussian discriminant analysis (LDA/QDA, §9.2), naive Bayes (§9.3), hidden Markov models.
Discriminative classifier: model the conditional directly
$$p(y=1\mid\boldsymbol{x},\boldsymbol{w})=\sigma(\boldsymbol{w}^\top\boldsymbol{x}+b)$$
Examples: logistic regression (Ch. 10), neural network classifiers (Ch. 13), and, in spirit, SVMs and decision trees.

A useful twist: same formula, different training

Section 9.3.4 shows that the two families can produce predictions of exactly the same shape.

If a Gaussian generative classifier shares one covariance across classes (LDA), or if you use naive Bayes with binary features, the posterior works out to

$$p(y=1\mid\boldsymbol{x})=\sigma\big(\boldsymbol{w}^\top\boldsymbol{x}+b\big),$$

which is exactly the logistic regression formula. They are called a generative–discriminative pair. So the real difference is not the shape of the answer. It is how the weights get chosen:

Generative training: fit the inputs and the labels
$$\max_{\boldsymbol\theta}\ \sum_n \log p(\boldsymbol{x}_n, y_n\mid\boldsymbol\theta)$$
$\boldsymbol{w}$ is then computed from the class means, covariances and priors.
Discriminative training: fit the labels only
$$\max_{\boldsymbol{w}}\ \sum_n \log p(y_n\mid \boldsymbol{x}_n,\boldsymbol{w})$$
$\boldsymbol{w}$ is tuned directly to predict labels well.

The generative objective spends effort modeling $p(\boldsymbol{x})$, which you never need for classification. When those modeling assumptions are right, that extra structure is a gift: it acts like extra information, and it lets you fit fast, handle missing inputs and use unlabeled data. When the assumptions are wrong, the extra structure is a burden, and the discriminative objective, which only cares about labels, tends to win. The rest of the page is that trade-off, one advantage at a time.

§9.4.1 — Where discriminative classifiers win

Three advantages from the chapter: better accuracy, freedom to engineer features, and probabilities you can trust.

9.4.1Better predictive accuracy

“$p(y\mid\boldsymbol{x})$ is often much simpler (and therefore easier to learn) than $p(\boldsymbol{x}, y)$.”

To classify, you only need the boundary. A generative model has to get all of $p(\boldsymbol{x}\mid y)$ right first, including bumps and quirks that have nothing to do with the boundary. If its assumed shape (say, one Gaussian per class) is wrong, those errors leak into the boundary. A discriminative model never models those bumps, so it can't be misled by them.

Where you see this
📷
Image recognitionWriting down a probability distribution over every possible photo of a cat is hopeless. Deciding whether a photo contains a cat is much easier. Modern image classifiers are discriminative neural networks.
💳
Fraud detection and click predictionTransactions or ad impressions have messy, many-humped feature distributions (time of day, amount, merchant type). Only the risk score is needed, so the industry standard is logistic regression or gradient-boosted trees.
🗣
Speech recognitionSystems moved from generative HMM–Gaussian-mixture acoustic models to discriminative neural networks largely for this reason.

9.4.1Can handle feature preprocessing

“Discriminative methods allow us to preprocess the input in arbitrary ways… It is often hard to define a generative model on such pre-processed data, since the new features can be correlated in complex ways.”

With logistic regression you can replace $\boldsymbol{x}$ by any feature vector $\phi(\boldsymbol{x})$: polynomials, word counts plus bigrams, embeddings, hand-crafted flags. The model doesn't care how those features relate to one another. A generative model has to describe the distribution of $\phi(\boldsymbol{x})$. Once $x_1$, $x_1^2$ and $x_1^3$ are all features, they are tightly tied together (one determines the others), and a simple density such as naive Bayes ignores those ties.

Where you see this
💬
Sentiment and text classificationFeatures like “contains not”, “contains good” and the bigram “not good” overlap heavily. Logistic regression on n-grams or TF–IDF is a classic strong baseline.
🧠
Classifiers on top of pretrained embeddingsA sentence or image embedding has hundreds of correlated dimensions. A logistic regression “probe” or a small neural head is the standard choice.
🏠
Tabular models with engineered featuresCredit or housing models add ratios, logs and interaction terms (income/debt, age×tenure). These are easy to add to a discriminative model and awkward to model generatively.

Naive Bayes gets worse and more confident at the same time. It treats $x_1$, $x_1^2$, $x_1^3,\dots$ as independent pieces of evidence, so the same information is counted many times.

9.4.1Well-calibrated probabilities

“Some generative classifiers, such as naive Bayes, make strong independence assumptions which are often not valid. This can result in very extreme posterior class probabilities (very near 0 or 1).”

A model is calibrated if, among all the cases where it says “80%”, about 80% really are positive. A weather forecaster who says 70% chance of rain is calibrated if it rains on about 70% of those days. When a decision depends on the actual number (should I approve this loan, how many nurses do I staff, what interest rate do I charge), calibration matters as much as accuracy.

Where you see this
🏥
Clinical risk scores“12% risk of readmission” drives follow-up decisions, so the number must mean what it says. Logistic regression is the workhorse here.
🏦
Credit scoring and insurance pricingExpected loss = probability × cost. A model that says 99.9% when the truth is 80% misprices everything.
📨
Spam filteringNaive Bayes spam filters famously output probabilities like 0.99999 or 0.00001. They often rank emails well, but the numbers themselves can't be trusted.

Takeaway. Set the correlation to 0% and naive Bayes's independence assumption becomes true, so both models are calibrated. Move it to 100%: naive Bayes now counts the same clue once per copy, and its confidence shoots toward 1 while the truth stays put. Logistic regression learns that the copies are redundant and splits the weight between them, so it stays calibrated.

§9.4.2–9.4.3 — Where generative classifiers win

Five advantages from the chapter. Almost all of them come from the same fact: the model knows what the inputs look like.

9.4.2Easy to fit

“Generative classifiers are often very easy to fit. For example… naive Bayes classifier… [and] discriminant analysis… by simple counting and averaging.”

A Gaussian or naive Bayes classifier is trained in one pass: count each class, average its points, compute their spread. That's a closed-form formula. Logistic regression has no closed form. You must run an iterative optimizer (gradient descent or Newton's method), which passes over the data many times, needs a stopping rule, and may need a learning rate tuned.

Where you see this
📨
Personal spam filters that learn as you clickWhen you mark an email as spam, a naive Bayes filter just bumps a few word counts. There's no retraining. That's a big reason the “Bayesian” spam filters popularized in the early 2000s were naive Bayes.
📡
Streaming data and tiny devicesRunning sums of counts, means and spreads can be updated one example at a time in constant memory, on a microcontroller or a data stream too large to revisit.
⏱
Quick baselinesNaive Bayes and LDA train in milliseconds even on huge datasets, so they make a good first sanity check before anything fancier.

Takeaway. The generative model is done before the first frame is drawn; its parameters are literally averages. Logistic regression has to search for its weights. Newton's method is faster than gradient descent, but it is still a loop, and every iteration touches every data point.

9.4.3Can easily handle missing input features

“Sometimes some of the inputs (components of $\boldsymbol{x}$) are not observed… With a generative classifier there is a simple method for dealing with this.”

If feature $x_2$ is missing, a generative model can marginalize it out. It asks how well each class explains the features you do have:

$$p(y=c\mid\boldsymbol{x}_1,\boldsymbol\theta)\ \propto\ p(y=c\mid\boldsymbol\theta)\int p(\boldsymbol{x}_1,\boldsymbol{x}_2\mid y=c,\boldsymbol\theta)\,d\boldsymbol{x}_2 \;=\; p(y=c\mid\boldsymbol\theta)\,p(\boldsymbol{x}_1\mid y=c,\boldsymbol\theta)$$
For a Gaussian, marginalizing just means deleting the missing rows and columns of $\boldsymbol\mu_c$ and $\boldsymbol\Sigma_c$. For naive Bayes it means dropping that feature's factor. (This assumes the feature is missing at random.)

A discriminative model learned $p(y\mid x_1, x_2)$ and has no idea what values $x_2$ tends to take, so there's no principled fix. In practice people impute a guess (often the average) or train a separate model for every pattern of missing features, which is up to $2^D$ models.

Where you see this
🩺
Medical diagnosisNot every patient gets every lab test. A generative model can still diagnose from whichever tests were run.
🌡
Sensor networks and robotsA weather station's humidity sensor fails, or a robot's camera is blocked. The classifier has to keep working with the sensors that remain.
📋
Surveys and formsPeople skip questions. Marginalizing over the skipped answers is more honest than filling in the average.

9.4.2Can fit classes separately

“In a generative classifier, we estimate the parameters of each class conditional density independently, so we do not have to retrain the model when we add more classes.”

Each class's $p(\boldsymbol{x}\mid y=c)$ is fit using only that class's examples. Adding a new class means fitting one new density and updating the class counts, while everything already learned stays put. In a discriminative model all the weights compete inside one softmax, so adding a class changes the right answer for every weight, and you retrain on everything.

Where you see this
👤
Face or voice recognition for a building or a phoneEnrolling a new employee or speaker should be instant. Classic speaker verification fits a Gaussian mixture model per speaker for exactly this reason.
🐦
Species identification appsNew species, or new regional variants, get added all the time. Retraining a giant model on every species for each addition is expensive.
✍
Handwriting or gesture systems with user-defined classesA user teaches the system a new symbol or gesture from a few examples.

9.4.2Can handle unlabeled training data

“We are often interested in semi-supervised learning… This is fairly easy to do using generative models… but is much harder to do with discriminative models.”

An unlabeled point still tells a generative model something: it must come from one of the classes, so the class densities should be placed where the data actually are. Treat the missing label as a hidden variable and run EM (see the §8.7 page). The E step softly labels the unlabeled points, and the M step refits the classes using everyone. A discriminative model only models $p(y\mid\boldsymbol{x})$, and an unlabeled point has no $y$, so it contributes nothing to the likelihood.

Where you see this
🩻
Medical imagingHospitals have millions of scans, but only a few have been labeled by a radiologist, whose time is expensive.
📰
Text classificationSorting news articles or support tickets: a few hundred are tagged, and the rest of the web is unlabeled. Naive Bayes + EM was a classic early method for this.
🔬
Science: cell types, galaxy shapes, protein familiesLabels require an expert or an experiment, but raw measurements are plentiful.

9.4.2May be more robust to spurious features

“A discriminative model may pick up on features of the input that can distinguish the classes in the training set, but which are not robust and which do not generalize beyond the training set… By contrast, generative models may be better able to capture the causal mechanisms of the underlying data generating process.”

A discriminative model will use any feature that separates the labels in the training data, whether or not it has anything to do with the class. If that shortcut changes in a new setting (distribution shift), accuracy collapses. A generative model is trained to explain how each class produces its inputs, $p(\boldsymbol{x}\mid y)$, which follows the causal direction (disease → symptoms, not symptoms → disease). Mechanisms like that tend to stay the same when the setting changes.

Notice that the chapter says “may be more robust.” This is not a guarantee. A generative model whose $p(\boldsymbol{x}\mid y)$ also includes the shortcut feature can be fooled too. The advantage comes from modeling the right mechanism, which is an active research area (e.g., invariant causal prediction).

Where you see this
🩻
Chest X-ray models that learned the hospitalPneumonia classifiers have been found to rely on scanner markers and hospital-specific text tags. Sicker patients were scanned on portable machines, so “portable-scanner marker” predicted the label without being about the lungs.
🐺
Wolf vs huskyIn a well-known demonstration (from the paper that introduced the LIME explanation method), a wolf-vs-husky classifier turned out to be a snow detector, because the wolf photos had snowy backgrounds.
🐄
Cows on beachesModels trained on cows in green pastures fail to recognize a cow on a beach.

Takeaway. The arrow pneumonia → lung shadows is biology, so it holds at every hospital. The link between the scanner marker and pneumonia is an accident of one hospital's workflow. A model that describes how each class generates its images is pushed toward the first arrow. A model that only hunts for whatever separates the training labels happily grabs the second one.

Rule of thumb

Lots of labeled data, complex inputs, and you only need the label or a trustworthy probability: go discriminative. Few labels, missing values, classes that keep arriving, a need for instant training, or a good idea of how the data are generated: go generative. And remember the generative–discriminative pair: naive Bayes and logistic regression can have the same formula, and only the training objective differs.
